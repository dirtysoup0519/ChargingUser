# 路线规划能力核对与后续规划

日期：2026-09-07  
分支：`map-navigation-ui`  
适用范围：首页站点、站点详情、路线预览、腾讯地图前端直连。

## 1. 核对结论

当前路线能力分为两条链路，不能混为一谈：

| 链路 | 当前状态 | 结论 |
| --- | --- | --- |
| 腾讯真实路线链路 | `TencentMapService::planRoute()` 调用 `/ws/direction/v1/driving/` 或 `/ws/direction/v1/walking/` | 已具备真实调用能力，需使用 `provider=tencent` 和有效 Key 人工联调 |
| 默认 Demo 链路 | `MockMapService` + `userdemomain.cpp::makeRoute()` | 仍是模拟数据，polyline 是起点/中点/终点三点直线，步骤和距离为合成值，不能作为真实导航效果验收 |
| 路线展示 | `TencentMapBridge` 将 `routePolyline` 传给 `resources/map/tencent-map.html` 的 `TMap.MultiPolyline` | 已具备腾讯底图上的折线展示能力，但必须用真实路线结果验证道路贴合、缩放和起终点 |
| 错误与并发 | requestId、取消、超时、鉴权/配额/网络/解析错误已有处理 | 逻辑基础已完成，仍需真实 Key 场景回归 |

因此，之前“路线规划是假的”的判断需要修正为：**生产适配器不是假的，默认 Demo 的路线数据是假的**。当前代码不能声称已经完成真实导航，因为还没有完成真实 Key 下的端到端验收，也没有实时 GPS、偏航重算或外部地图唤起。

## 2. 代码证据与边界

### 已完成

1. `TencentMapService::planRoute()` 根据 `TravelMode` 选择 driving/walking 端点，并发送起点、终点和 Key。
2. `handleRoutePayload()` 校验腾讯响应，转换 duration（分钟→秒），解析差分编码 polyline，并清理步骤中的 HTML 标签。
3. `MapUiBinder` 通过 requestId 接收路线结果，映射为 `NavigationViewState`，处理空结果、失败、重试和迟到响应。
4. `TencentMapBridge` 对 polyline 做坐标校验后发送到 WebChannel；腾讯 JS 使用 `TMap.MultiPolyline` 绘制。
5. Mock 服务保留可控的成功、空结果、失败、超时和取消测试能力。

### 尚未完成或容易误判

1. `configureMapDemo()` 仍为每个站点注入 `makeRoute()` 结果；默认启动若未切换供应商，不会访问腾讯路线接口。
2. 当前 Demo 配置文件默认 `provider=mock`，这是为了无 Key 启动和自动回归，不代表真实路线不可用。
3. 腾讯路线 polyline 的真实道路贴合、驾车/步行差异、配额和 Key 权限尚未在当前自动测试中验证。
4. 路线页是“路线预览”，不是实时导航：没有连续定位、偏航检测、自动重算、语音播报或腾讯地图 App 深链。
5. 站点列表点击后的地图居中联动仍需补齐 JS 侧选中站点定位；这与路线服务本身是两个独立问题。

## 3. 更新后的实现顺序

### 阶段 A：先修复展示联动

- 将 `selectedStationId` 纳入地图快照更新，列表点击后由 JS 按 stationId `setCenter`，不再只修改降级画布偏移。
- 增加多站点 `FitStations` 和单站点 `CenterStation` 的一次性 camera 命令。
- 验收：点击任意站点行/标记，地图只移动到对应站点；程序性移动不触发“搜索当前区域”。

### 阶段 B：真实腾讯路线端到端联调

- 本地配置保持在被忽略的 `config/tencent-map.local.json` 或进程环境变量中，不写入仓库。
- 设置 `provider=tencent`，分别测试驾车和步行；记录请求是否成功、路线距离/时长、polyline 是否落在道路上。
- 验证站点详情进入路线页时，目的地始终来自当前 stationId 的权威坐标；快速切换站点时旧响应不能覆盖新结果。
- 验收：真实路线摘要、步骤和腾讯底图折线一致；配额、鉴权、网络和超时错误可区分展示。

### 阶段 C：处理 Demo 数据策略

- 保留 `MockMapService` 作为无网络自动测试和 UI 回归后端。
- 将 `makeRoute()` 明确标注为测试夹具，禁止把其步骤/距离用于真实能力验收。
- 可增加“真实腾讯模式/模拟模式”启动提示，避免测试人员误以为默认路线来自腾讯。

### 阶段 D：路线产品化前置工作

- 后端返回站点坐标、坐标系和入口点语义；前端只负责适配和展示。
- 确认是否需要多路线、途经点、交通状态或新能源偏好；每项都要先扩展 DTO 和验收标准。
- 如要做实时导航，再单独设计定位、权限、后台运行、偏航重算和外部地图唤起，不复用当前“路线预览”接口冒充完成。

## 4. 验收命令与记录要求

自动测试不得使用真实 Key 或访问公网，重点覆盖：polyline 解码、单位转换、空路线、非法响应、超时、取消和迟到响应。

真实联调只在本地执行，至少记录：

- Qt/WebEngine 版本、运行平台和供应商模式；
- 驾车/步行各一条成功路线的距离、时长和地图截图；
- Key 权限或配额错误时的界面文案与错误码；
- 是否发生重复请求、路线串页或地图折线偏移。

## 5. 当前开发优先级

1. 修复站点点击后的地图居中。
2. 用真实腾讯模式完成驾车/步行路线人工联调。
3. 在 Demo 和文档中显式区分 Mock 路线与真实路线。
4. 再决定是否扩展实时导航能力；在此之前不删除现有路线 DTO 和 `IMapService::planRoute()`，因为它们已经是可用的真实供应商适配边界。
