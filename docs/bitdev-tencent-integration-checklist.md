# BitDev 腾讯地图联调清单

日期：2026-09-07；分支：`map-navigation-ui`（基线 `18240a5`）；适用人：实机联调执行人。

本文是 `docs/tencent-map-frontend-integration.md` 中"仍需真实 Key 人工联调"一项的执行清单。
每项都给出操作步骤与预期结果；任何一项不符合预期，记录实际现象与错误码后交给逻辑负责人排查。

## 0. 准备

- [ ] `git checkout map-navigation-ui && git pull`，确认最新提交 ≥ `18240a5`
- [ ] 构建正式工程：项目根目录 `qmake && make -j4`（BitDev 若默认 qmake6，按最新文档用 Qt 6.2.4 + WebEngineWidgets；Qt 5.15.3 环境可先做功能联调，正式验收以文档为准）
- [ ] 设置 Key（不写入任何文件）：`export TENCENT_MAP_KEY=你的Key`，仅当前终端有效
- [ ] Key 泄漏自查：`git grep 你的Key` 必须无结果；确认 Key 没进 diff、截图与日志

## 1. 无 Key 快速失败（先做，不消耗配额）

- [ ] 清空变量（`unset TENCENT_MAP_KEY`）后启动 demo，触发一次地址搜索
- 预期：不发起网络请求，界面收到 `map-config-missing` 错误文案，可恢复操作

## 2. 地理编码链路（/ws/place/v1/suggestion）

- [ ] 首页输入地址关键词（如"深圳北站"）触发搜索
- 预期：返回候选列表；`candidateId` 为腾讯返回 id；点选后地图中心到所选点
- [ ] 输入无意义字符串（如乱码）
- 预期：空候选或 `map-provider-error`，均不崩溃、界面可重试
- [ ] 检查请求域名：抓包或日志确认命中 `apis.map.qq.com/ws/place/v1/suggestion`

## 3. 路线规划链路（/ws/direction/v1/{driving,walking}）

- [ ] 站点详情 → 查看路线，默认驾车
- 预期：起终点标记正确；距离（米）、时长（**分钟→界面按小时/分钟显示**）、文字步骤可读（无 HTML 标签残留）；地图 polyline 落在路上而非水域/建筑（验证数组解码）
- [ ] 切换步行
- 预期：一次点击只发一个请求（步骤列表与时长明显变化）；无重复应答串扰
- [ ] 驾车/步行各跑一条深圳-广州级别的长路线
- 预期：距离数值合理（百公里级），polyline 点数与路线长度成比例

## 4. 可靠性场景（重点）

- [ ] 快速切站：详情页 A/B 快速来回点击查看路线
- 预期：最终展示的永远是最后点选站点的结果（requestId 关联 + 迟到应答丢弃）
- [ ] 请求进行中点返回/再切换
- 预期：无崩溃，无迟到结果串页
- [ ] 断网触发路线请求
- 预期：`map-network` 错误、提示可重试；恢复网络后重试成功
- [ ] 超时：路由器断流（不拒连、只吞包）或等 10s
- 预期：约 10s 后 `map-timeout` 可重试错误

## 5. 错误码对照（遇到即记录）

| 现象 | 预期错误码 | 含义 |
|---|---|---|
| 未设 Key | `map-config-missing` | 本地快速失败 |
| 频率/配额超限 | `map-rate-limited`（可重试） | 控制台配额页核对 |
| Key 无效/未勾 WebServiceAPI | `map-provider-error`（不可重试） | 回控制台检查产品勾选 |
| 无网络 | `map-network`（可重试） | |
| 响应截断/异常 | `map-parse`（不可重试） | 记录原始响应交给逻辑负责人 |
